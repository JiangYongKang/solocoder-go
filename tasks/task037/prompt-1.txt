在当前项目中实现一个 API 版本化路由功能模块。
1. 实现 URL 路径版本策略：在 URL 路径中携带版本号，例如 `/v1/users` 和 `/v2/users` 分别路由到不同版本的处理器，框架从路径中提取版本号并选择对应的处理函数。
2. 实现请求头版本策略：在 HTTP 请求头中通过自定义头字段（如 `API-Version`）指定版本号，框架从请求头中读取版本号来决定使用的处理器版本，路径中不体现版本信息。
3. 实现查询参数版本策略：在 URL 查询参数中通过指定参数名（如 `?version=v1`）携带版本号，框架从查询参数中提取版本号来路由到对应处理器。
4. 实现版本间请求的自动兼容转换：当客户端请求的版本与最新服务版本不一致时，支持注册请求和响应的转换函数，自动将旧版本请求格式转换为新版本格式，处理完成后再将新版本响应格式转换回旧版本格式返回给客户端。
5. 代码实现和单测需要放在 internal/apiver/ 包下，然后为该模块编写完整的单元测试，覆盖正常流程、边界条件和异常分支。
6. 运行 go test ./internal/apiver/ -v，需要让所有测试通过。
7. 在 docs/apiver.md 中编写模块需求文档，说明模块功能、核心结构体的职责、三种版本策略的优先级与组合规则以及使用示例。
