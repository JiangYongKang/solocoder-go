你实现的内容安全策略引擎模块在 data URI 修复中引入了过度放宽的安全问题，需要修复：
1. processAttributes 方法使用 `strings.HasPrefix(mimeType, "image/")` 将 image/ 前缀下所有子类型一概放行，包括 `image/svg+xml`。SVG 是 XML 格式的矢量图形，可内嵌 `<script>` 标签和 `onload` 事件处理器，当 `data:image/svg+xml,<svg onload=alert(1)>` 通过 src 属性注入时浏览器会解析并执行其中的 JavaScript，形成 XSS 攻击向量。修复 data:image/png 被误拦截的回归不应允许可脚本化的 SVG 格式，应对 image/svg+xml 做脚本内容检测或仅允许不含事件处理器和 script 标签的版本。
2. processAttributes 的 data URI 白名单过度扩展，包含了 `text/css`、`application/json`、`application/octet-stream` 以及 `application/vnd.*` 通配前缀。提示词原本只要求恢复 data URI 图片的被拦截问题，未要求对 CSS 样式代码、JSON 数据或厂商自定义二进制格式做安全放行，`application/vnd.*` 通配覆盖了 vnd.ms-excel 等可触发外部应用行为的类型，在不必要地扩大攻击面。应把白名单收缩到提示词要求的范围，非必要类型一律不放行。
3. 修复后需要为上述问题补充对应的单元测试，验证 SVG XSS 被正确拦截、不必要的白名单类型被移除。
4. 运行 go test ./internal/contentsec/ -v，需要让所有测试通过。
