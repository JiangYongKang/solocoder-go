产物不满意：
1. colstore.go 中 Config.DictionaryEnabled 字段从未被任何代码引用。NewColumnStoreWithConfig 虽接收配置，但 encode 和 appendValues 方法无条件执行字典编码，无论 DictionaryEnabled 是 true 还是 false 压缩始终生效。根本原因是模型设计了配置开关但在核心编码路径中遗漏了条件分支。应在 encode 和 decode 中根据配置决定是否走字典编码。
2. compareValues 函数处理类型不匹配时用 fmt.Sprintf 将值转为字符串后按字典序比较，而非返回类型不兼容错误。这导致 int(1) 与 string("1") 在 OpEq 下被判定相等。类型 switch 只覆盖了四种类型的具体组合，缺少对不兼容类型对的显式错误处理。应返回比较错误或规定不兼容时跳过该谓词。
3. Column 内部维护了独立的 sync.RWMutex，但这些列级方法全部在 ColumnStore 已持有全局锁的 Write 或 Read 内部调用，列级锁从未独立使用。每次列操作需在全局锁基础上再获取列级锁，增加锁竞争却无并发收益。应去除列级锁消除冗余。

过程不满意：
1. 模型一次性写完 colstore.go 全部 400 余行代码，再一次性写完测试，然后才运行 go test。全量编码再验证的策略导致 Config.DictionaryEnabled 未接入编码逻辑的设计缺陷被固化。正确做法是先实现基础读写功能并跑通测试，再逐步叠加字典编码和谓词过滤，每完成一个子特性立即验证。
2. 首次 go test 仅发现空行写入测试失败，模型定位到 Write 中 early return 将列创建提前后修改通过即宣布完成。但未进一步审查 Write 中其他校验分支是否存在类似"校验成功后才执行副作用"的问题，也未检查列边界越界等风险。应在修复一处后排查同一函数内所有校验路径，确保无相似模式缺陷。
