产物不满意：
1. adaptiveStreamWriter.Write 方法底部有一条永远走不到的 `return len(p), nil`，因为在它之前的所有分支都已经 return 了。虽然不影响运行但对维护者是误导，让人以为还有没覆盖的分支逻辑，属于该清理的死代码。
2. initCompressor 里 `a.actual.Write(a.buf)` 的返回值用 `_` 丢掉了，只靠 error 判断写入是否成功。如果压缩 writer 发生了无错误的短写，没刷出去的缓冲区数据就悄无声息丢了。虽然目前 gzip/snappy/lz4 的 writer 通常不会短写，但按 io.Writer 接口约定应该检查写入字节数。
3. 新增的约 9 个测试用例统一用 `mgr, _ := NewManager(cfg)` 忽略构造错误。万一 Config 被误改成非法值，测试就会因为 nil 指针 panic 而不是给出清晰的错误提示，降低了测试的可调试性和健壮性。

3. 模型首次跑 go test 全部 PASS 但发现测试日志里压缩后大小显示 0 字节——因为日志打印在创建 decompressor reader 之后，reader 创建消耗了 compressedBuf 内容导致 Len 变成 0。模型又改了 3 次来调不同测试用例的日志输出时机。这是写完测试后没考虑共享 buffer 状态的副作用，属于试错式补充修改，应该一次性把日志打印时机处理好。
