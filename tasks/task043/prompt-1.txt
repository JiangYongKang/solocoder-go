在当前项目中实现一个 CSRF 防护中间件功能模块。
1. 实现同步令牌模式：服务端为每个用户会话生成唯一的 CSRF Token 并存储在服务端会话中，渲染表单时将 Token 嵌入隐藏字段，收到 POST 等状态变更请求时从请求体中提取 Token 并与服务端存储的值比对，不匹配或缺失时返回 403 拒绝请求。
2. 实现双重提交 Cookie 模式：服务端生成 CSRF Token 后同时设置到 Cookie 和响应头中，客户端在后续请求中从 Cookie 读取 Token 并放入自定义请求头，服务端比对 Cookie 中的 Token 与请求头中的 Token 是否一致，一致则放行否则返回 403。
3. 实现 Token 绑定到会话：每个 CSRF Token 必须与当前用户会话绑定，不同会话之间 Token 不可互换使用，会话销毁时对应的 Token 也应失效，防止攻击者将一个合法 Token 用于不同会话。
4. 实现请求来源校验：对状态变更请求校验 Origin 和 Referer 请求头，请求来源不与当前服务域名匹配时直接拒绝，提供白名单机制允许配置合法的跨域来源。
5. 实现 Token 轮换：每次成功使用 Token 完成一次请求后立即生成新的 Token 替换旧 Token，旧 Token 立即失效不可再次使用，防止 Token 泄露后被重放攻击。
6. 代码实现和单测需要放在 internal/csrf/ 包下，然后为该模块编写完整的单元测试，覆盖正常流程、边界条件和异常分支。
7. 运行 go test ./internal/csrf/ -v，需要让所有测试通过。
8. 在 docs/csrf.md 中编写模块需求文档，说明模块功能、核心结构体的职责、两种防护模式的工作原理以及使用示例。
