产物不满意：
1. snaptest.go 的 Match 方法在快照文件不存在时自动将当前数据写入快照并返回匹配成功。提示词要求"快照文件只有在更新命令显式调用时才会改变"，自动创建行为让快照在普通 Match 调用时就被改变了，首次测试无论输出正确与否都通过因为快照源自未经验证的输出。正确做法是快照不存在时返回错误提示用户先通过 Update 生成基线快照。
2. snaptest.go 中定义了错误变量 ErrSnapshotMismatch 但整个模块中没有任何函数返回或使用这个错误。Match 在比对不一致时返回 false, report, nil 将差异信息放在返回值字符串而非用错误变量包装。文档中将其列为错误定义会让调用方误以为可通过 errors.Is 判断差异类型，应删除或在比对失败路径中实际使用。
3. normalizeSnapshotContent 使用 strings.TrimRight 删除内容尾部所有换行符导致数据丢失。如果快照以空行结尾 TrimRight 会将尾部空行一并裁掉，原本 "a\nb\n\n" 归一化后变成 "a\nb" 尾部空行被静默丢弃。一旦被测数据产生尾部空行就会因归一化而比对通过掩盖了真实差异。应改为 TrimSuffix 只删除末尾单个换行符。
4. 差异可视化输出的 Format 方法生成的是统一差异格式而非提示词要求的并排格式。提示词要求以行级并排格式展示原始快照和当前输出的不同之处，但当前实现输出的是类 git unified diff，删除行和新增行各占一行，无法在同一行同时看到快照和当前内容的对应关系。
过程不满意：
1. 模型在实现前阅读了 retry.go、retry_test.go 等多个无关任务包的源代码作为"代码风格参考"。这些包分属其他任务编号内含不同领域的功能逻辑，与当前 snaptest 任务无任何技术关联。项目规则要求不同任务包隔离，跨越任务边界阅读其他任务的实现代码是不必要的探索，消耗上下文且未带来有效信息。
2. 模型在整个开发过程中未意识到 Match 方法首次自动创建快照的行为与提示词第四条存在矛盾。文档中甚至将此行为描述为正常特性，说明模型没仔细核对每一项约束条件，下意识套用了 Jest 等主流快照测试工具的自动创建模式，将外部工具的设计理念带入当前任务而未逐条对照提示词验证。
