你实现的服务注册与发现模块存在一些并发安全和通知语义问题，需要修复：
1. Start 方法在 r.running 为 true 的分支中，先释放了 r.mu 锁，之后才调用 r.wg.Add(1) 启动新的后台协程。在解锁和 Add 之间的时间窗口内，并发调用 Stop 方法可能导致 Stop 中的 wg.Wait() 在 Add 之前返回，后续新协程的 wg.Done() 会在已完成的 WaitGroup 上执行，违反 sync.WaitGroup 的契约。
2. notifySubscribersLocked 方法的命名带有"Locked"后缀暗示调用者需持锁且执行期间锁不释放，但该方法内部执行了解锁和重新加锁操作。在 expireInstances 中被调用时，每发送一个服务的通知就经历一次解锁-重新加锁循环，导致多服务间的过期通知不是原子的。通知释放锁的间隙中其他协程可能注册新实例，使后续服务的"过期"通知中包含不应出现的新注册实例。
3. expireInstances 方法发送过期通知时，实际是重新查询当前实例列表来构建通知内容，而非使用扫描阶段遗留的过期前状态快照。当发生变化的服务超过一个时，前一个服务的通知释放锁后可能有新实例注册到后一个服务中，导致后一个服务的过期通知错误携带了未过期的活跃实例。
4. 修复以上问题后，需要为该模块补充并发 Start/Stop 交叉场景、多服务过期通知一致性的单元测试。
5. 运行 go test ./internal/servicereg/ -v，需要让所有测试通过。
6. 在 docs/servicereg.md 中更新模块需求文档。
