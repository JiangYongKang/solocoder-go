在当前项目中实现一个 GraphQL 查询解析器功能模块，使用内存数据结构模拟数据源。
1. 实现 Schema 定义：支持用 Schema Definition Language 定义类型系统，包括对象类型、字段类型、非空标记、列表类型以及 Query 和 Mutation 两种操作类型的声明，Schema 定义完成后可查询已注册的类型和字段信息。
2. 实现字段解析器注册：支持为 Schema 中每个类型的每个字段注册对应的解析函数，解析函数接收父类型数据和查询参数返回该字段的值，解析器支持返回标量值、对象值和列表值，同一字段重复注册时后者覆盖前者。
3. 实现查询验证：在执行查询前对查询语句进行验证，验证内容包括请求的字段是否在 Schema 中已定义、字段的参数类型是否匹配、嵌套查询的深度是否超出限制以及必选字段是否缺失，验证失败时返回明确的错误信息指出具体哪个字段或路径不合法。
4. 实现嵌套查询的批量数据加载：支持 DataLoader 模式避免 N+1 查询问题，当同一层级的嵌套查询包含多个父对象的子字段加载时先收集所有待加载的键再通过一次批量加载函数统一获取数据最后分发到各父对象，批量加载函数由外部注册。
5. 代码实现和单测需要放在 internal/gqlparser/ 包下，然后为该模块编写完整的单元测试，覆盖正常流程、边界条件和异常分支。
6. 运行 go test ./internal/gqlparser/ -v，需要让所有测试通过。
7. 在 docs/gqlparser.md 中编写模块需求文档，说明模块功能、核心结构体的职责、DataLoader 批量加载的工作流程以及使用示例。
